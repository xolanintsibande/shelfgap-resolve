# Product Discovery Plan

## Objective

Test whether shelf-gap investigation is a sufficiently frequent, costly or frustrating problem, and whether a guided case workflow would improve the current process.

## Key assumptions to test

1. Users currently use inconsistent methods to report and investigate shelf gaps.
2. The cause is not always visible from the initial shelf observation.
3. Relevant evidence is distributed across physical checks and records.
4. Cases can lack clear ownership or follow-up.
5. A guided workflow would be usable during store operations.
6. A separate tool would add value beyond existing retailer systems.

Do not treat these assumptions as findings until research supports them.

## Interview participants to seek

- Store replenishment staff.
- Store supervisors.
- Retail field representatives.
- Inventory / receiving staff.
- Retail operations or category analysts, if accessible.

Aim for a small first round of 5–8 interviews if practical. This is exploratory research, not a statistically representative sample.

## Interview questions

1. Think about the last time you found a product missing from its expected shelf position. What happened?
2. How was the issue recorded?
3. What did you check first?
4. Which records or people did you need to consult?
5. What made the investigation easy or difficult?
6. How did you decide the cause?
7. What happened when the first explanation was wrong?
8. Who was responsible for the corrective action?
9. How did you know the issue was resolved?
10. How often do similar issues recur?
11. What tools or systems are already used?
12. What information would you not want to enter into a new tool?
13. What would make this workflow too slow to use?
14. If you could change one part of the process, what would it be?

Avoid leading questions such as “Would this app be useful?” Ask about actual past behaviour first.

## Evidence capture template

For each interview, record:
- Participant role (no name required).
- Date and consent status.
- Current workflow.
- Specific recent example.
- Pain points stated in the participant's own words.
- Workarounds.
- Frequency indicators, if they can reliably estimate them.
- Existing systems.
- Privacy or access constraints.
- Product implications.
- Contradictory evidence.
- Researcher interpretation, clearly separated from participant statements.

## Discovery decision

Proceed to prototype only if interviews show a recurring, actionable workflow problem and the proposed tool does not duplicate an adequate existing solution. Otherwise, revise the problem or explore an improvement to an existing process.
